# 架构

## 全貌

![系统全貌](/figures/overview.png)

自左向右：公开泄露面（24 站点）经采集、检测、判定入库三步进入引擎，右侧以告警、处置、面板三路输出；发现窗口由人工巡检的以天计压缩到分钟级。

## 四层流水线

![四层架构](/figures/architecture.png)

系统按依赖方向分四层：入口层（cli / daemon / batch）依赖契约层（core 的数据模型、注册表与扫描引擎），插件层（channels / detectors）import 即装配，出口层（response / panel）只依赖契约层，不存在反向依赖。

![检测流水线](/figures/pipeline.png)

命中处理的两阶段设计：先按行收集全部命中做分组，再逐行组装 Finding 并执行全行掩码——同一行的兄弟凭据一并掩码，这是系统的安全红线之一。

## 数学模型

四个环节各有经生产数据校验的模型：采集层信息年龄 `E[R]=T/2+c`（拟合误差 <4%）；检测层正则并语言单调不减，新增规则只扩大命中集合；增长层发现流呈负二项过散，渠道覆盖以子模贪心取 `(1−1/e)` 近似；调度层配额约束下的最优轮询周期服从平方根律。
